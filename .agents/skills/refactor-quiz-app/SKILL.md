# Refactor Quiz App

퀴즈 앱의 기능이나 디자인은 바꾸지 않고, 초보자도 이해하기 쉬운 구조로 꼼꼼하게 정리한다.
Playwright로 테스트할 때도 기존과 동일한 화면과 동작이 나오는지 확인한다.
AGENETS.md, PRD.md, README.md 를 업데이트한다.

## 작업 순서

1. 현재 구조 파악
   - HTML, CSS, JavaScript 파일과 실행 방식을 확인한다.
   - 문제 데이터, 상태, 채점, 화면 렌더링, 이벤트 처리 위치를 찾는다.
   - 리팩터링 전 주요 흐름과 화면을 실행해 기준 동작을 기록한다.

2. 역할 분리
   - 문제 배열은 별도의 데이터 모듈로 옮긴다.
   - 현재 문항, 점수, 정답 판별, 재시작 같은 진행 로직을 한곳에 모은다.
   - 질문, 선택지, 진행률, 결과 화면을 갱신하는 코드는 화면 모듈이나 작은 렌더 함수로 정리한다.
   - 앱 시작 파일은 모듈을 연결하고 이벤트를 전달하는 역할만 맡긴다.

3. 단순하게 정리
   - 기존 프로젝트가 빌드 도구 없는 Vanilla JavaScript라면 ES Modules를 사용한다.
   - 작고 명확한 함수와 이름을 사용하고, 불필요한 클래스나 복잡한 추상화는 만들지 않는다.
   - HTML 구조, CSS 클래스, 문항 내용, 점수 기준, 사용자 흐름은 변경하지 않는다.

4. 검증
   - JavaScript 문법과 모듈 경로 오류를 확인한다.
   - 10문항 표시, 선택 후 다음 문제 이동, 점수 계산, 결과 메시지, 다시 시작을 확인한다.
   - 데스크톱과 모바일 UI가 리팩터링 전과 동일한지 비교한다.
   - 가능하면 `playwright-preview-check` Skill로 화면, 핵심 동작, 콘솔 오류, 스크린샷을 확인한다.

## 완료 보고

- 생성하거나 변경한 파일과 각 역할을 간단히 설명한다.
- 기능과 UI가 유지되었는지 검증 결과를 적는다.
- 실패하거나 확인하지 못한 항목은 원인과 함께 숨김없이 보고한다.

## 주의사항

- 리팩터링과 관계없는 기능 추가, 디자인 변경, 문항 수정은 하지 않는다.
- 기존 동작을 먼저 이해한 뒤 파일을 나누며, 한 번에 지나치게 많은 계층을 만들지 않는다.
- 사용자 변경 사항이 있으면 되돌리지 말고 현재 코드에 맞춰 작업한다.
