# Movie Quiz Data Batch

이 프로젝트의 Supabase DB에 영화 퀴즈 문제를 유형별로 100개씩 안전하게 추가하거나 기존 데이터 분포를 검수한다.

## 실행 모드

- 사용자가 특정 유형의 문제를 **추가**해 달라고 하면 전체 워크플로를 실행한다.
- 사용자가 데이터 **분포 또는 무결성 검수**만 요청하면 조회와 보고만 수행한다. DB를 변경하지 않는다.
- 요청 유형이 모호하면 생성 전에 정확한 유형명 하나를 확인한다.

## 필수 원칙

- Supabase MCP로 실제 스키마를 먼저 확인한다. 기억이나 이전 대화의 스키마를 그대로 가정하지 않는다.
- 기존 테이블, 컬럼, 제약조건, RLS, 문제 유형을 임의로 변경하거나 새로 만들지 않는다.
- 요청한 유형이 `quiz_question_types`에 없으면 삽입을 멈추고 사용자에게 보고한다.
- 추가 요청은 정확히 새 문제 100개와 선택지 400개를 대상으로 한다.
- 사실이 불확실하거나 출처 간 내용이 충돌하는 문제는 사용하지 않는다.
- 실패나 부분 삽입을 숨기지 않는다. 성공 수, 실패 수, 원인을 정확히 보고한다.

## 1. 사전 점검

Supabase MCP를 사용해 다음을 순서대로 확인한다.

1. 접근 중인 프로젝트와 DB 연결 상태를 확인한다.
2. `quiz_question_types`, `quiz_questions`, `quiz_options`의 컬럼, 타입, 기본값, PK/FK, 필수값과 제약조건을 확인한다.
3. 문제 유형 코드와 표시 이름을 조회해 사용자의 표현을 실제 유형 한 개에 매핑한다.
4. 아래 기준으로 삽입 전 수치를 기록한다.

- 전체 문제 수
- 유형별 문제 수
- 난이도별 문제 수
- 요청 유형의 전체 문제 수와 난이도별 문제 수
- 전체 선택지 수

기존 문제의 질문 문구, 정답, 영화·인물명을 충분히 조회해 중복 검사 기준으로 사용한다. 페이지 제한이 있으면 모든 행을 나누어 조회한다.

## 2. 문제 100개 생성

요청한 한 가지 문제 유형에 맞춰 아래 구성을 정확히 지킨다.

| 난이도 | 개수 |
| --- | ---: |
| `easy` | 45 |
| `normal` | 35 |
| `hard` | 20 |

각 문제는 다음 조건을 모두 만족해야 한다.

- 질문 1개, 해설 1개, 선택지 4개
- 정답 선택지는 정확히 1개
- 오답도 질문과 같은 범주의 그럴듯한 값으로 작성
- 정답 위치는 1~4번에 각각 25개씩 배치
- 질문만 읽어도 답을 하나로 결정할 수 있도록 작품명, 연도, 국가 등 필요한 범위를 명시
- 같은 사실을 표현만 바꿔 반복하지 않기
- 동일한 영화, 배우, 감독, 작곡가의 과도한 반복 피하기
- 기존 문제와 문구·정답·핵심 사실이 같거나 지나치게 비슷한 문제 제외
- 해설에는 정답과 판단 근거를 짧고 명확하게 포함

영화 정보는 공식 영화사·배급사, 영화제·시상식 공식 사이트, 제작진 공식 자료, 공신력 있는 영화 데이터베이스 등 신뢰할 수 있는 자료로 확인한다. 개봉 연도처럼 국가별 기준이 달라질 수 있는 정보는 기준 국가나 최초 공개 기준을 질문에 명시한다. 확인하기 어려운 명대사 번역, 흥행 순위, 현재 시점 순위처럼 모호하거나 변동 가능한 사실은 피한다.

## 3. 삽입 전 검증

DB를 변경하기 전에 생성한 100개 전체를 구조화된 목록으로 점검한다.

- 총 문제 수 `100`
- 난이도 분포 `45 / 35 / 20`
- 총 선택지 수 `400`
- 문제별 선택지 수 `4`
- 문제별 정답 수 `1`
- 정답 위치 분포 `25 / 25 / 25 / 25`
- 빈 질문, 빈 선택지, 빈 해설 없음
- 한 문제 안의 선택지 중복 없음
- 생성 배치 내부의 질문 중복 없음
- 기존 DB 문제와 정규화된 질문 문구 또는 핵심 사실 중복 없음

하나라도 맞지 않으면 삽입하지 말고 해당 항목을 수정한 뒤 전체 검증을 다시 실행한다.

## 4. Supabase 삽입

실제 확인한 스키마에 맞춰 `quiz_questions`를 먼저 추가하고 생성된 문제 ID에 연결해 `quiz_options`를 추가한다.

- 문자열 연결보다 JSON/구조화 데이터와 PostgreSQL의 안전한 파싱 방식을 우선한다.
- SQL 문자열의 작은따옴표와 특수문자를 정확히 이스케이프한다.
- 문제와 선택지 관계를 보존할 수 있도록 명시적인 키 매핑을 사용한다.
- 가능하면 하나의 트랜잭션으로 처리한다.
- 도구 입력 크기 때문에 나눠야 하면 20~25문제 단위로 삽입하고 각 배치 직후 검증한다.
- 부분 실패 시 이미 들어간 문제 ID를 기록하고 같은 문제를 다시 삽입하지 않는다.
- 스키마 변경 migration은 실행하지 않는다.

## 5. 삽입 후 검증

추가한 문제 ID만 대상으로 먼저 무결성을 확인한 뒤 전체 집계를 다시 조회한다.

반드시 확인할 항목:

- 전체 문제 수가 삽입 전보다 정확히 `100` 증가
- 요청 유형 문제 수가 정확히 `100` 증가
- 난이도별 증가량이 `easy +45`, `normal +35`, `hard +20`
- 전체 선택지 수가 정확히 `400` 증가
- 추가된 모든 문제에 선택지 4개 존재
- 추가된 모든 문제에 정답 선택지 1개 존재
- 정답 위치가 1~4번 각각 25개
- 고아 선택지, 잘못된 문제 유형, 빈 해설 없음
- 기존 데이터와 새 데이터 사이에 명백한 중복 없음

무결성 조회는 문제별로 그룹화해 `option_count <> 4` 또는 `correct_count <> 1`인 행을 찾는다. 결과가 한 행이라도 있으면 완료로 보고하지 말고 원인과 영향을 받은 문제 ID를 제시한다.

## 결과 보고

완료 후 아래 내용을 짧게 요약한다.

- 대상 Supabase 프로젝트와 요청 문제 유형
- 삽입 전후 전체 문제 수
- 요청 유형의 삽입 전후 문제 수
- 삽입된 난이도 분포
- 문제 수, 선택지 수, 정답 수 검증 결과
- 중복 및 사실 검수 결과
- 실패 또는 제외된 항목과 이유

검수 전용 요청에서는 현재 전체·유형별·난이도별 분포와 무결성 위반만 보고하고 데이터를 수정하지 않는다.

## 사용 예시

- `movie-quiz-data-batch Skill을 사용해서 영화 제목 맞히기 유형 100개를 추가해줘.`
- `movie-quiz-data-batch Skill을 사용해서 감독 맞히기 유형 100개를 추가해줘.`
- `movie-quiz-data-batch Skill을 사용해서 현재 데이터 분포를 검수해줘.`
